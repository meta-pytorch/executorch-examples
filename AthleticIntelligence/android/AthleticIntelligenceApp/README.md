# Athletic Intelligence for Android

This Android app performs on-device whole-body pose inference for squat coaching. It runs an RTMW ExecuTorch program with the XNNPACK backend. Inference does not require a network connection.

This is a coaching prototype. It is not a medical device, a diagnostic tool, or a substitute for a qualified coach or clinician.

## Requirements

- An ARM64 Android device (`arm64-v8a`) running Android 8.0 (API 26) or later. The APK intentionally contains no x86, x86-64, or 32-bit ARM runtime.
- Android SDK 34 and Android build tools.
- JDK 17.
- Camera permission at runtime.
- Sufficient free storage for the RTMW model, session data, and annotated videos.

The exporter lock resolves with Python 3.11 on an ARM64 host running macOS 14 or later. The Android app does not require Python.

## Build and install

Open this directory as the Android Studio project, or build from a shell:

```bash
# Create local.properties with your own Android SDK path, for example:
printf 'sdk.dir=%s\n' "$ANDROID_HOME" > local.properties

./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Gradle resolves the Android runtime from Maven as `org.pytorch:executorch-android:1.1.0`. The project also expects `rtmw_l_int8.pte` in `app/src/main/assets/`. Model binaries are ignored by Git, so a source-only checkout must export the model before building. See [RTMW export](#rtmw-export) and [MODEL_LICENSES.md](MODEL_LICENSES.md).

## RTMW export

The scripts in `tools/rtmw/` download one pinned OpenMMLab archive, verify it, fix the model to the app's `1 x 3 x 384 x 288` input, convert ONNX to PyTorch, and lower the result to an ExecuTorch XNNPACK program. The export environment pins ExecuTorch 1.1.0 to match the Maven Android dependency, together with its required `torchao==0.15.0` and a compatible `torch==2.10.0`/`torchvision==0.25.0` pair. This prevents a newer exporter from silently producing a program for the older app loader. The int8 path uses deterministic file ordering and requires representative calibration images; it never silently substitutes random calibration data.

Create the pinned Python environment:

```bash
uv venv --python 3.11 .venv-rtmw
source .venv-rtmw/bin/activate
uv pip sync tools/rtmw/requirements-lock.txt

python tools/rtmw/download_rtmw.py
```

Export FP32:

```bash
python tools/rtmw/export_rtmw.py \
  --onnx tools/rtmw/artifacts/end2end.onnx \
  --output tools/rtmw/artifacts/rtmw_l_fp32.pte
```

Export int8 with representative upright RGB camera frames. The exporter applies the same aspect-preserving black letterbox and normalization as the Android runtime. Calibration data affects quantization scales and the output hash, so preserve the exact image set and the content digest printed by the script with any released model:

```bash
python tools/rtmw/export_rtmw_int8.py \
  --onnx tools/rtmw/artifacts/end2end.onnx \
  --calibration /path/to/calibration-images \
  --output tools/rtmw/artifacts/rtmw_l_int8.pte
```

After validating the model on the target device, place it in the app assets and rebuild:

```bash
install -m 0644 tools/rtmw/artifacts/rtmw_l_int8.pte \
  app/src/main/assets/rtmw_l_int8.pte
./gradlew :app:assembleDebug
```

The exporters print the output SHA-256. PyTorch and backend changes, host architecture, and a different calibration corpus can change generated bytes even when inference remains valid. Before releasing a new model, run the export and load the result with `org.pytorch:executorch-android:1.1.0` on a target device; dependency resolution alone does not validate a serialized program.

## Privacy and storage

- The manifest does not request Internet access. Pose inference runs on the device.
- Camera frames are processed locally.
- Session summaries, frame telemetry, and annotated squat videos are stored in the app's private files directory. Platform backup is disabled, and Android normally removes these files on uninstall.
- Choosing Share creates a ZIP in the app cache and hands it to the Android share sheet. Data leaves the device only through the destination that the user selects. Cache files can remain until Android or the user clears app storage.

Review recordings and exports before sharing them: video and pose telemetry can reveal identity, location context, health-related movement, and performance information.

## Limitations

- Results depend on lighting, camera placement, visibility, clothing, motion blur, device thermals, and whether the full body remains in frame.
- The pose model estimates two-dimensional landmarks from a monocular camera. It does not measure true depth, force, or clinical joint loading.
- RTMW-l is used on the full camera frame without a separate person detector. Empty or ambiguous scenes can produce false landmarks; confirm that the overlay follows the athlete before relying on a session.
- Scores and movement feedback are heuristic coaching signals. Do not use them for safety-critical, medical, employment, or eligibility decisions.
- CPU/XNNPACK performance varies by ARM64 device. Long sessions can throttle or consume substantial battery.
